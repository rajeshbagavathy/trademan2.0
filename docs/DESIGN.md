# Tradman design

This is the product, the architecture, and the decisions already taken. Read it before changing the engine, a broker adapter, a strategy rule, or the page. Later work should extend these decisions. Do not reopen them unless the person using the desk asks.

The diagram in `Trading-Engine-Architecture.png` is the same shape: a strategy emits intents, the engine journals them, and a broker adapter is the only code that speaks a broker protocol.

## Product

Tradman is a paper multi-leg options desk. It is meant to feel like AlgoTest's live page, not like a raw order blotter.

- Rust engine, React monitor. One process serves the command and snapshot API. The page only sends commands and reads snapshots.
- Paper only. There is no live order path. Do not add broker passwords, tokens, API keys, or session cookies to the repository.
- Brokers in the design are Firstock and 5paisa XTS. The running desk uses recorded fixtures and the paper adapter. Selecting a broker on Activate records that name. It does not log in and it does not send an order to that broker.
- Price failover is not order failover. A second feed may replace a dead price feed. An order stays with the broker that accepted it.
- Every strategy is multi-leg. One leg failing after another has been sent flattens the whole book.
- The page has no left rail and no button that places a raw order. Commands are activate, pause, resume, square off, and parameter updates.

## Crate boundaries

| Folder | Package | Owns |
| --- | --- | --- |
| `crates/core` | `tradecore` | Integer prices, unit quantities, VWAP, signed P&L |
| `crates/broker-api` | `broker-api` | Identifiers, sides, products, intents, order events, the `Execution` trait |
| `crates/strategy` | `strategy` | A book of legs. Events in, intents out. No I/O |
| `crates/engine` | `engine` | Tick gate, feed arbiter, journal-before-send, order manager |
| `crates/adapter-paper` | `adapter-paper` | Paper fills |
| `crates/adapter-sim` | `adapter-sim` | Broker simulator used by tests |
| `crates/adapter-firstock` | `adapter-firstock` | Firstock frame parsing. No dependency on strategy or engine |
| `crates/adapter-xts` | `adapter-xts` | XTS frame parsing, lot conversion, order bucket. No dependency on strategy or engine |
| `crates/api` | `api` | In-memory desk, strategy definitions, HTTP |

The package in `crates/core` is named `tradecore` because a crate named `core` shadows Rust's `libcore`.

Adapters must not depend on `strategy` or `engine`. Broker-specific parsing stays in the adapter. The strategy never sees a broker payload.

## Money and quantity

Prices inside the engine are integer ticks. One tick is one paisa, so rupees times 100. `PriceTicks` and `QtyUnits` are the only price and size types on the hot path. The page divides by 100 in `ui/src/lib/utils.ts` (`inr` and `px`).

Quantity on a book is exchange units, not lots. Lot size is applied when a definition is materialized:

| Underlying | Lot size | Paper spot | Strike step |
| --- | --- | --- | --- |
| NIFTY | 65 | 22500 | 50 |
| BANKNIFTY | 30 | 48000 | 100 |
| FINNIFTY | 65 | 23500 | 50 |
| MIDCPNIFTY | 50 | 12000 | 25 |
| SENSEX | 20 | 80000 | 100 |

Those spots are fixed until an underlying feed exists. ATM is the nearest strike, `(spot + step / 2) / step * step`. ITM and OTM are one step, not AlgoTest's ITM1 through OTM30. OTM call and ITM put are ATM plus one step. ITM call and OTM put are ATM minus one step. With the NIFTY spot, an OTM call is `NIFTY 22550 CE` and an OTM put is `NIFTY 22450 PE`.

`execution.multiplier` multiplies the unit quantity. Product defaults to MIS. NRML is the other stored choice.

## How an order is born

```
Create  ->  saved definition, phase Waiting
Activate  ->  queue until entry_time, or enter now if that time has passed
entry_time  ->  Book::activate emits Place intents
engine  ->  journal, then the paper adapter
fills and ticks  ->  Book::on_event / Book::on_tick emit modify, stop, or flatten intents
```

The strategy crate does not send anything. It returns `Intent::Place`, `Intent::Modify`, or `Intent::Cancel`. The engine writes the intent to the journal before the adapter sends it.

`IntentPriority` is Flatten, then Stop, then Trail. The order manager stores the priority. It does not yet reorder a queued batch by that priority.

Client order ids are generated by the book. Firstock fixtures carry that id in `remarks`. XTS uses `TagMap` because XTS tags are not the core id. `units_to_lots` uses `checked_div`.

## Multi-leg safety

Entry is all-or-nothing. If any entry leg is rejected, partially filled and then stuck, times out, or its protective stop cannot be placed, the book flattens every leg that has a position.

- The fill window is `Params.fill_window_ms`, default 2000. `on_time` ignores a leg that was never sent (`sent_ms` is `None`), so a momentum leg that is still waiting does not flatten the book.
- A stop reject while the book is still `Entering` flattens. A reject after the book is `Live` is ignored. That is a known gap, not the desired end state.
- A duplicate fill is detected by the last `(qty, price)` fingerprint on that leg, not by a trade id.
- Combined P&L is realized on closed quantity plus unrealized on open marks. Realized is frozen at the exit fill. The exit used for P&L is the VWAP of the exit fills, not the stop trigger price.
- `Phase::Halted` exists and is never set.

## Stops, trails, and momentum

Leg stop and leg trail modify the broker stop. They do not invent a second exit order while the stop is working.

- Points stop: sell trigger is entry plus points times 100.
- Percent stop: sell trigger is entry plus entry times percent / 100.
- An unset stop still places a stop at the entry price so the leg is protected.
- Underlying points, underlying percent, and delta are stored. Underlying modes pass offset 0, so the trigger stays at the entry. Delta is not a `SlMode` and is stored as off. Do not pretend these move the stop until an underlying or delta feed exists.
- Leg trail is points only. Every X points of favorable move, the stop moves by Y. Percent and delta trails were removed from the product. A trail value of zero means the trail is off.
- Strategy stop, strategy target, lock, lock-and-trail, and overall trail default to the close of a 1-minute candle. The execution dialog can select LTP or a 3-minute candle. Candle boundaries are measured from the book's own origin plus the interval.
- Overall target and stop accept MTM rupees or a percent of total premium. MTM is signed ticks: a stop of 2000 rupees is stored as `-200000` ticks.
- Lock arms when profit reaches the lock level, then holds the floor. Lock-and-trail keeps moving that floor. Overall trail moves the strategy stop by the configured points.
- Wait-and-trade is `Params.wait_distance`. Unset means the rule is off. If it is set, activate stays in `Waiting` and sends nothing until the move arrives.

Momentum:

- A leg only uses premium percent of that leg's own option: `PremiumUp` or `PremiumDown`. Points momentum on a leg does not release it.
- The first tick on a waiting leg stores the reference premium and does not order. A later tick releases the entry after the percent move.
- Overall momentum (`Params.momentum`) holds every leg until the combined premium has moved. Percent uses the whole percent. Points use ticks (rupees times 100). All legs need a reference and a mark. The check is the sum of marks against the sum of references.
- If only some legs have premium momentum and the book momentum is off, the unconditional legs are entered immediately and the others wait.
- The paper API does not pump live premium ticks. A momentum leg therefore stays unsent until something calls `on_tick`. The audit line is `{id} held N entry until the selected premium move`.

## What the form saves but the engine does not enforce

These fields are on `Definition` and the React types so the form can round-trip them. They do not change orders today. Wire them up only when that feature is requested. Do not delete them in passing.

- Range breakout on a leg.
- Underlying and delta stop or target.
- Entry and exit order style (limit or market protection), buffers, trigger-versus-traded reference, delay seconds, continuous versus delayed monitoring, and the delayed frequency.
- Weekdays and DTE. They are displayed and saved. They do not block activation.
- Strategy type (intraday, BTST, positional), square-off partial versus complete, and trail-to-breakeven.
- Exit time. The book does not square off by itself when `exit_time` arrives.
- Re-entry was removed on purpose from legs and from overall settings. Do not add it back unless asked. Old JSON that still contains re-entry fields will fail to deserialize.

## Scheduling

`entry_time` is a local `HH:MM` on the machine running the API. `local_offset_ms` is the real timezone offset on Windows and on macOS or Linux. Tests set `Desk.offset_ms = 0` so day math is UTC.

`activate` calls `activate_at(id, broker, now)`. If today's entry time is still ahead, the strategy is `Queued`, `starts_at` is set, and no orders are sent. `snapshot` calls `release_due` on every poll. When `starts_at` is due and the strategy is not paused, `enter_now` runs. If the entry time has already passed, it enters immediately and `started_at` is now.

Pause of a queued strategy skips `release_due`. Resume only clears the flag. The next snapshot enters if the time has passed. Square off while the book is still `Waiting` cancels the queue and returns the strategy to the Activation list. It does not send orders. Square off is allowed for Entering, Live, and Paused. It is not offered for Flat.

The page polls `GET /api/snapshot` about once a second. The countdown also ticks once a second in the browser from `starts_at` and `started_at`.

## HTTP

Bind `127.0.0.1:8090`. Do not move it back to 8080. On some Windows machines 8080 returns permission error 10013. The Vite dev server is `127.0.0.1:5173` and proxies `/api` to 8090. macOS uses the same ports.

| Method | Path | Effect |
| --- | --- | --- |
| GET | `/api/snapshot` | Release due strategies, then return the desk |
| POST | `/api/strategies` | Save a definition in Waiting |
| POST | `/api/strategies/activate-inactive` | Activate every saved strategy |
| POST | `/api/strategies/{id}/activate` | Queue or enter. Body is `{ "broker": "Firstock" }` or 5paisa |
| POST | `/api/strategies/{id}/execution` | Replace execution settings |
| POST | `/api/strategies/{id}/pause` | UI pause flag |
| POST | `/api/strategies/{id}/resume` | Clear the pause flag |
| POST | `/api/strategies/{id}/square-off` | Flatten, or unqueue if still waiting |

The desk is in memory. Restarting the API reseeds two books and drops anything created in the page.

The seeded Nifty book is not built by `materialize`. It is a replayed fill history, and its instruments are `22500 CE` and `22500 PE`. A newly saved Nifty strategy uses `NIFTY 22500 CE`. Keep those different. The seeded put closed at 133.85 (13385 ticks), realized loss 380.25 rupees (38025 ticks). The call is marked at 118.00 and its unrealized profit is 1592.50 rupees (159250 ticks). Combined is 1212.25 rupees (121225 ticks). `seeded_put_is_frozen_at_the_fill_not_the_trigger` locks those numbers. Do not "fix" the seed by materializing it from the sample definition.

Bank Nifty starts saved, broker label 5paisa, overall stop 3000 rupees, phase Waiting.

## Feeds and adapters

`TickGate` drops a tick that goes backward in exchange time or jumps by more than the configured band. `Arbiter` drops a disabled feed and a tick older than the last forwarded tick for that instrument. `stale_feeds` reports a feed quiet for longer than `stale_after_ms`.

Firstock market frames use `i_last_traded_price`, `prcftr`, `i_feed_time`, and `c_symbol`. A Firstock session with no pong within 10 seconds is dead. That watchdog is part of the adapter design. The paper desk does not open a socket.

XTS market data uses touchline only, message code 1501. Depth (1502) and candle (1505) frames are fixtures and are ignored by `parse_market`. The order bucket allows 10 sends per second. The 11th is delayed, not dropped.

## Page

React 19, Vite 6, Tailwind 3.4, IBM Plex Sans. The page background is light (`#f4f6f8`). Indigo is the primary action color. Green and red are reserved for profit and loss.

Top navigation, full width, no left rail:

- **Create** is only the builder. Save posts the definition and lands on Algo trade.
- **Algo trade** has two sections. **Executions** is everything that is not Waiting, sorted by `entry_time` ascending, with a running or countdown timer. **Activation** is Waiting only, with Edit execution and Activate.
- **Orders**, **Fills**, and **Audit** are read-only tables from the snapshot.

Edit execution already edits multiplier, LTP or candle close (1 minute or 3 minutes), MIS or NRML, delay seconds, entry and exit order style, target and stop reference, buffers, continuous or delayed monitoring, weekdays, DTE 0 through 6, and auto square-off on margin error. Saving those fields must keep working even while some of them are not enforced by the book.

The Activate dialog offers Firstock and 5paisa. It posts the broker name. It must not grow a raw order form.

## Builder choices that are intentional

Strike criteria is only "Strike type", and the next control is only ITM, ATM, or OTM. Leg trail is only None or Points. Leg momentum is only None, premium percent up, or premium percent down, measured on that leg's option premium. The value box appears only when the choice is not None. Overall momentum still has points up, points down, percent up, and percent down, because that rule is implemented. Re-entry controls stay gone.

## How to change the engine

Write the test first, watch it fail, then make it pass. After a module change run, from the repository root:

```bash
cargo fmt --all
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
```

For a page change, from `ui`:

```bash
npx tsc --noEmit
```

Do not weaken a test to make a change pass. Do not add `chrono` or another time crate for the local offset. The offset helpers in `crates/api/src/main.rs` are the clock.

When a page flow changes, exercise it against the paper API: Create, save, confirm it is only under Activation, Activate, confirm it is on the Executions board with the timer. Use an entry time later than the current local time when the countdown needs to be visible. Do not place a live broker order while doing that.

## Not built yet

These were discussed and then deferred. They are the remaining product, not permission to invent a different architecture.

- A real Firstock socket and a real XTS market-data plus interactive session, still behind the adapter trait, still paper-gated until a separate explicit decision allows live orders.
- Reconciliation of positions against the broker net, an unprotected-position alert, and a watchdog that notices a missing stop.
- Using the broker's own order update as the exit price when a stop fills in slices, then VWAP across those slices.
- Exit-time square off, weekday and DTE filters, range breakout, and underlying or delta stops, once a feed for those inputs exists.
- A persistent store. The desk forgets user-created strategies on restart.
- A premium tick pump, so a saved momentum rule can release without a hand-fed tick.
- Reordering the order manager by `IntentPriority`.
- Setting `Phase::Halted` when the book must stop trading but must not flatten again.
